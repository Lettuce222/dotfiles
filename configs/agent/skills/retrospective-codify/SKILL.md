# Retrospective Codify

「最初に知っていれば遠回りしなかったこと」を、将来も検証できる最小の仕組みに変える。
記録を増やすこと自体は目的にせず、提案ゼロも妥当な結論として扱う。

## 対象

使う場面:

- 誤った初手や仮説から、再利用可能な解法に到達した
- 同種の失敗を静的検査や手順で防ぎたい
- ユーザーが振り返りや知見の固定化を求めた

使わない場面:

- 一度限りの事実で、コミットや PR の説明だけで十分
- 好みや状況依存の判断を普遍的な規則にできない
- 新しい知見が既存の仕組みで十分にカバーされている

## ワークフロー

1. タスクの証拠から次を対応付ける。
   - 最初の試行と失敗
   - 最終的に通った解法
   - 両者を分けた気付き
2. 気付きを、将来の作業で判断に使える 1〜3 文へ一般化する。
3. 関連語を 2〜3 個選び、リポジトリ内の既存資産を検索する。
   - linter / formatter / ast-grep の設定とルール
   - `AGENTS.md` / `CLAUDE.md`
   - 関連する `SKILL.md`
   - 実装ドキュメントやテスト
4. 既存資産との関係を `新規` / `既存を拡張` / `完全重複` /
   `判断保留` のいずれかに整理する。
5. 下の分類基準で、最小の出力先を選ぶ。
6. 変更前に提案と想定 diff を示し、ユーザーが選んだ項目だけを実装する。

## 分類基準

優先順位は次のとおり。

1. 構文や設定として検出できるなら、既存 linter / formatter /
   ast-grep のルールとテストにする。
2. 複数ステップの作業や文脈判断が必要なら、既存 Skill の拡張または
   新しい Skill を検討する。
3. 静的検査できず、ほぼ全タスクで必要な短い契約だけを
   `AGENTS.md` / `CLAUDE.md` の候補にする。
4. リポジトリをまたぐ恒久的な仕事の知識として保存する意図があるなら、
   承認後に `ws` へ引き継ぎ、dotfiles の汎用指示へ混ぜない。
5. 個人的な好み、局所的な文脈、一時的な feedback は tracked file に固定しない。
   セッションの記録や製品の auto-memory に委ねる。
6. 一度限りの事実、十分に重複している知見、将来の探索空間を不必要に
   狭める規則は追加しない。

境界が曖昧なら、強いルールへ昇格させず `判断保留` として根拠を示す。

## 出力先ごとの契約

### 静的検査

`ast-grep-practice` またはプロジェクト既存の検査基盤を使う。
検出規則だけでなく、valid / invalid ケースと実行方法まで提案に含める。
自動修正が意味や副作用を変え得る場合は、診断のみを選ぶ。

### Skill

この Skill から `SKILL.md` を直接設計・編集しない。
学び、想定利用場面、ワークフロー骨子、既存 Skill との関係を引き継ぎ要旨にし、
承認後に `skill-creator` へ委譲する。

### AGENTS.md / CLAUDE.md

既存セクションへ収まる短い契約として提案する。
詳細手順、長い例、機械判定可能な禁止事項は常時コンテキストへ置かない。
理由は例外判断に必要な範囲だけ添える。

### Auto-memory

この Skill は auto-memory のファイルを検索・作成・更新しない。
柔らかい feedback が自動記憶に適している場合は、tracked artifact の候補から外し、
「製品の auto-memory に委ねる」とだけ報告する。

### Vault

仕事をまたぐ恒久知識は、保存案の承認後に `ws` へ委譲する。
仕事固有の内容をこの Skill や dotfiles 管理の指示へ書き込まない。

## 提示フォーマット

```markdown
## Retrospective
- 最初の失敗: <観測した事実>
- 最終解: <通った解法>
- 気付き: <再利用可能な判断>

## 提案
- [lint | skill | instruction | vault] <対象>: <変更の要旨>
  - 根拠: <既存資産との関係>
  - 検証: <テストまたは確認方法>

## 追加しない知見
- <知見>: <完全重複、一度限り、auto-memory に委ねる、判断保留など>
```

空の節は省く。提案がなければ、その理由だけを明示する。

## 安全境界

- 提案の承認前にルール、Skill、設定を変更しない。
- 既存資産を削除候補にする場合、使用実績をファイルだけから推測しない。
- 検証・レビュー手順は不要とみなさず、必要時に呼ぶ独立 Skill として評価する。
- 仕事固有の文脈を dotfiles の汎用設定へ移さない。

## 関連

- `ast-grep-practice` — 構造的な検出・修正ルール
- `skill-creator` — Skill の作成・改訂・評価
- `ws` — 承認済みの恒久的な仕事知識を Vault へ保存
- `empirical-prompt-tuning` — Skill や指示の実行評価
