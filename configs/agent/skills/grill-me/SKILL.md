# Grill Me

ユーザーの計画・設計・アイデアを、質問を重ねて共通理解に到達するまで掘り下げるインタビュー。目的は、ユーザー自身がまだ言語化していない前提・依存関係・未決定事項を表に出し、決定を一つずつ確定させること。

## 進め方

1. **対象の把握**: まず grill 対象の計画がどこにあるかを確定する。会話履歴で既に語られていればそれを使い、ドキュメントやファイルが指されていれば読む。まだ何も無ければ「何についての計画か、現時点の考えを一度語ってください」と最初に引き出す。
2. **質問ループ**: 一度に 1 問だけ聞く（複数の論点を 1 メッセージに詰めるとユーザーの思考が分散する）。1 問は 1 つの決定に対応させる。各質問には自分の推奨回答と理由を 1〜2 文で添える。ユーザーは同意するだけでも先に進めるが、回答が推奨と違ったらそちらを正として次へ進む。AskUserQuestion ツールが使える環境では、選択肢化できる質問はそれで提示し、推奨案に "(Recommended)" を付ける。
3. **掘る順序**: 目的と制約（何のために・何が動かせないか）を最初に固め、そこに依存する決定を根から葉へ辿る。ある決定が別の未決定に依存していると分かったら、依存先を先に片付ける。ユーザーが別の枝に飛んだらそれに付き合い、戻るべき未解決の枝は自分が覚えておいて後で戻す。
4. **調べられることは聞かない**: コードベース・ドキュメント・Web で事実確認できる質問は、ユーザーに聞かずに自分で調べ、結果を踏まえた次の質問をする。対象がコードを持たない計画（組織・イベント・キャリアなど）でも同じで、資料や Web で確認できる事実はユーザーに聞かない。ユーザーに聞くのは、ユーザーにしか決められない判断・好み・優先度だけ。
5. **収束**: 新しい論点が出なくなった、または主要な枝がすべて「決定」か「意図的な保留」になったら、掘り下げをやめて収束フェーズに入る。ユーザーが「もう十分」と言ったら即座に収束する。relentless なのは質問の深さであって、ユーザーの終了判断より優先しない。

## 収束時のアウトプット

最後に以下を短くまとめて提示し、認識齟齬がないか確認する:

- **決定事項**: 合意した決定と、その理由を一行ずつ
- **意図的な保留**: 今は決めないと合意したことと、それを決めるトリガー
- **次アクション**: あれば

まとめの保存先（Vault・ドキュメント・issue 等）はユーザーの判断。仕事の全体観に属するテーマなら ws skill での capture を一言提案してよいが、勝手には書かない。
